# ログ設計

## 1. ログの目的

- 障害調査
- 利用状況の可視化
- 監査・コンプライアンス

## 2. ログレベル定義

| レベル | 用途                                     |
| ------ | ---------------------------------------- |
| FATAL  | サービス継続不可となる重大障害           |
| ERROR  | 機能単位の失敗                           |
| WARN   | 想定外だが継続可能な状態                 |
| INFO   | 重要なイベント（ログイン、決済成功など） |
| DEBUG  | 開発・調査時のみ                         |

## 3. ログフォーマット

- 構造化ログ（JSON）を基本とする
- 共通フィールド：`timestamp`, `level`, `service`, `traceId`, `userId`, `message`
- 個人情報・機微情報はマスクして出力する

## 4. 出力先・収集

- 標準出力 → ログ収集基盤（CloudWatch / Datadog / ELK 等）
- アクセスログ、アプリケーションログ、監査ログを分けて管理

## 5. 保存期間

| 種別           | 保存期間 | 保存先           |
| -------------- | -------- | ---------------- |
| アクセスログ   | 90 日    |                  |
| 監査ログ       | 1 年以上 |                  |
| デバッグログ   | 7 日     |                  |

## 6. 監視・アラート

- ERROR / FATAL 発生時の通知ルール
- 異常検知（エラー率、レイテンシ）
