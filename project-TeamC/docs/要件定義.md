# 要件定義

### 1. ドキュメント情報

- **ドキュメント名**：学習進捗管理アプリ 要件定義
- **作成日**：2026/06/09
- **作成者**：TeamC
- **バージョン履歴**：
  - v0.1：MVP設計内容をもとに初期作成
  - v0.2：MVP範囲、role別表示、投稿種別、認可方針などを修正
  - v0.3：実装済みの画面構成、投稿種別選択、Docker Compose構成に合わせて更新

---

### 2. プロジェクト概要

- **システム名**：学習進捗管理アプリ
- **システムの目的・背景**：
  - オンラインスクールの生徒が、日報や進捗報告を記録し、自分の過去の学習内容を振り返れるようにする。
  - 現状、日報はDiscord、進捗報告はGoogleフォームで行っているため、過去の投稿を生徒自身が一覧で振り返りにくい課題がある。
  - 生徒は自分の投稿を作成・一覧表示・編集・削除できる。
  - 講師は、生徒全員分の投稿を一覧表示できる。
  - `student` / `teacher`　のroleによって、表示内容と利用できる機能を分離する。
  - 投稿は`daily_report`と`progress_report`の2種類から選択できる。
- **関係者**：
  - 講師：生徒の学習状況を確認する
  - 利用者：オンラインスクールの生徒
  - 開発チーム：TeamC

---

### 3. 用語定義

| 用語     | 定義                                                              |
| -------- | ----------------------------------------------------------------- |
| MVP      | 最初に実装する最小限の機能範囲                                    |
| 投稿     | 生徒が学習内容や進捗を記録するデータ                              |
| 日報     | その日の学習内容や取り組みを記録する投稿                          |
| 進捗報告 | 学習の進み具合、困っていること、次にやることなどを記録する投稿    |
| 投稿種別 | 投稿を分類するための種別。`daily_report` または `progress_report` |
| student  | 投稿を作成し、自分の投稿を確認・編集・削除できる生徒ユーザー      |
| teacher  | 生徒全員分の投稿を一覧・詳細表示できる講師ユーザー                |
| role     | `student` / `teacher` のユーザー権限                              |
| JWT      | ログイン済みユーザーを識別するための認証トークン                  |
| CRUD     | 作成、取得、更新、削除の基本操作                                  |

---

### 4. 業務フロー（As-Is / To-Be）

- **現在の業務（As-Is）**：
  - 日報はDiscordに投稿している。
  - 進捗報告はGoogleフォームで行っている。
  - 生徒自身が過去の投稿を一覧で振り返れない。
  - 投稿内容を後から編集・削除しにくい。

- **新システムでの業務フロー（To-Be）**：
  - 生徒または講師がログインする。
  - 生徒は日報または進捗報告を作成する。
  - 生徒は自分の投稿一覧を確認する。
  - 生徒は投稿の詳細を確認する。
  - 生徒は自分の投稿を編集・削除する。
  - 講師は生徒全員分の投稿一覧を確認する。
  - 講師は各投稿の詳細を確認んする。
  - ユーザーはログアウトする。

### 5. 機能要件

| ID     | 機能名                 | 概要                                   | 詳細仕様                                                                                              |
| ------ | ---------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| FR-001 | ログイン機能           | ユーザーがログインできる               | メールアドレスとパスワードで認証し、成功時にJWTを発行                                                 |
| FR-002 | ログアウト機能         | 　ユーザーがログアウトできる　         | 　フロントエンド側で保持しているJWTを削除し、ログイン画面へ戻る　                                     |
| FR-003 | ログイン中ユーザー取得 | ログイン中のユーザー情報を取得する     | JWTを検証し、ユーザーID・名前・メールアドレス・roleを取得                                             |
| FR-004 | 投稿作成               | 生徒が投稿を作成できる                 | `student` のみ作成可能。投稿内容をAPIへ送信し、DBに保存                                               |
| FR-005 | 投稿種別選択           | 投稿種別を選択できる                   | `daily_report`または`progress_report`を選択                                                           |
| FR-006 | 投稿一覧表示           | roleに応じて投稿一覧を表示する         | `student` は自分の投稿のみ表示、`teacher` は生徒全員分の投稿を表示                                    |
| FR-007 | 投稿詳細表示           | 投稿の詳細を表示する                   | `student` は自分の投稿、`teacher` は生徒全員分の投稿詳細を表示可能                                    |
| FR-008 | 投稿編集               | 生徒が自分の投稿を編集できる           | `student` は自分の投稿のみ編集可能。他人の投稿は編集できない。`teacher` や管理者による編集はMVP対象外 |
| FR-009 | 投稿削除               | 生徒が自分の投稿を削除できる           | `student` は自分の投稿のみ削除可能。他人の投稿は削除できない。`teacher` や管理者による削除はMVP対象外 |
| FR-010 | 権限制御               | roleに応じて利用できる機能を制御する   | 権限判定はバックエンドで行い、許可されていない操作は拒否する                                          |
| FR-011 | 未認証アクセス制御     | 未ログインユーザーのアクセスを制限する | 認証が必要な画面へアクセスした場合はログイン画面へ戻す                                                |
| FR-012 | 不正トークン制御       | 不正・期限切れJWTの利用を防止する      | JWT検証に失敗した場合は認証状態を解除し、ログイン画面へ戻す                                           |

| ID      | 機能名           | 概要                                                 | 詳細仕様                                                 |

| FR-G001 | 絞り込み機能     | 講師側で投稿一覧を条件で絞り込む                     | 生徒名、投稿日、投稿種別などで絞り込む                   |
| FR-G002 | ステータス管理   | 講師が確認状況を管理する                             | 未確認 / 確認済み / 要フォローなどのステータスを設定可能 |
| FR-G003 | ページネーション | 投稿件数が増えた場合に分割表示する                   | 一度に取得・表示する投稿数を制限する                     |
| FR-G004 | 専用管理画面     | 講師向けの管理者機能がついた詳細な管理画面を表示する | MVP完了後に必要に応じて検討                              |
| FR-G005 | 新規登録         | 新しいユーザーがアカウントを作成する                 | メールアドレスとパスワードで登録する                     |

### 8. データ要件

- ユーザー情報を管理する。
- 投稿データを管理する。
- ユーザーは `student` または `teacher` のroleを持つ。
- 投稿データは、投稿したstudentユーザーと紐づけて保存する。
- 投稿には `type` を持たせ、`daily_report` または `progress_report` を管理できるようにする。
- 作成日時と更新日時を保存する。
- MVPでは新規登録画面を実装しないため、動作確認用の `student` / `teacher` ユーザーはseedデータとして作成する。

> 詳細は [`DB 設計`](./DB設計.md) を参照。

### 9. 外部連携・API 要件

MVPでは外部サービス連携は行わない。
アプリ内部のAPIとして、以下を利用する。

| API             | 概要                               | 方法     | 形式 |
| --------------- | ---------------------------------- | -------- | ---- |
| `/auth/login`   | ログイン処理                       | REST API | JSON |
| `/me`           | ログイン中ユーザー取得             | REST API | JSON |
| `/reports`      | roleに応じた投稿一覧取得・投稿作成 | REST API | JSON |
| `/reports/{id}` | 投稿詳細取得・編集・削除           | REST API | JSON |

> 詳細は [`API 設計`](./API設計.md) を参照。

### 10. 制約事項・前提条件

- フロントエンドは Next.js / TypeScript を使用する。
- バックエンドは Python / FastAPI を使用する。
- DBは PostgreSQL を使用する。
- ORMは SQLModel を使用する。
- 認証方式は JWT を使用する。
- frontend、backend、dbはDocker Composeで起動する。
- MVPでは新規登録画面は実装しない。`student` / `teacher` ユーザーはseedデータとして作成する。
- `student`は自分の投稿のみ作成・取得・編集・削除できる。
- `teacher`は生徒全員分の投稿を取得できる。
- MVPでは `teacher` は生徒全員分の投稿を一覧表示できるが、投稿の作成・編集・削除などの管理者機能は対象外とする。
- 講師向けの一覧表示画面での絞り込み、ステータス管理、専用管理画面は Good to have とする。
- PCブラウザでの利用を前提とする。

---

### 11. 現在の既知の課題

- 存在しない投稿IDの編集画面では、取得エラーと空の編集フォームが同時に表示される。
- 投稿件数が増えた場合のページネーションは未実装。
- 本番環境へのデプロイ、監視、バックアップはMVP対象外とする。

---

### 12. リスクと対応方針

- 講師向けの詳細な管理機能まで実装する時間が足りない可能性がある
  - MVPでは `teacher` が生徒全員分の投稿を一覧表示できるところまで実装し、絞り込み、ステータス管理、専用管理画面はGood to haveとして扱う。
