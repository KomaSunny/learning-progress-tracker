# 要件定義

### 1. ドキュメント情報

- **ドキュメント名**：学習進捗管理アプリ 要件定義
- **作成日**：2026/06/09
- **作成者**：TeamC
- **バージョン履歴**：
  - v0.1：MVP設計内容をもとに初期作成

---

### 2. プロジェクト概要

- **システム名**：学習進捗管理アプリ
- **システムの目的・背景**：
  - オンラインスクールの生徒が、日報や進捗報告を記録し、自分の過去の学習内容を振り返れるようにする。
  - 現状、日報はDiscord、進捗報告はGoogleフォームで行っているため、過去の投稿を生徒側が一覧で振り返りにくい課題がある。
- **関係者**：
  - 講師：生徒の学習状況を確認する
  - 開発チーム：TeamC
  - 利用者：オンラインスクールの生徒

---

### 3. 用語定義

| 用語 | 定義                                             |
| ---- | ------------------------------------------------ |
| MVP  | 最初に実装する最小限の機能範囲                   |
| 日報 | 学習内容や進捗を記録する投稿                     |
| JWT  | ログイン済みユーザーを識別するための認証トークン |
| CRUD | 作成、取得、更新、削除の基本操作                 |

---

### 4. 業務フロー（As-Is / To-Be）

- **現在の業務（As-Is）**：
  - 日報はDiscordに投稿している。
  - 進捗報告はGoogleフォームで行っている。
  - 過去の投稿を生徒自身が一覧で振り返りにくい。

- **新システムでの業務フロー（To-Be）**：
  - 生徒がログインする。
  - 生徒が日報・進捗報告を作成する。
  - 生徒が自分の投稿一覧を確認する。
  - 生徒が自分の投稿を編集・削除する。
  - Good to haveとして、講師が生徒全員分の投稿を確認できる管理画面を追加する。

---

### 5. 機能要件

| ID     | 機能名             | 概要                               | 詳細仕様                                        |
| ------ | ------------------ | ---------------------------------- | ----------------------------------------------- |
| FR-001 | ログイン機能       | ユーザーがログインできる           | メールアドレス＋パスワードで認証、JWT 利用      |
| FR-002 | 日報・進捗投稿作成 | 生徒が日報や進捗報告を作成できる   | 入力内容をバックエンドAPIへ送信し、DBに保存する |
| FR-003 | 投稿一覧表示       | 生徒が自分の投稿一覧を確認できる   | ログイン中のユーザー本人の投稿のみ表示する      |
| FR-004 | 投稿編集           | 生徒が自分の投稿を編集できる       | 他人の投稿は編集できない                        |
| FR-005 | 投稿削除           | 生徒が自分の投稿を削除できる       | 他人の投稿は削除できない                        |
| FR-006 | 管理画面           | 講師が生徒全員分の投稿を確認できる | Good to have機能として扱う                      |

### 8. データ要件

- ユーザー情報を管理する。
- 日報・進捗投稿を管理する。
- ユーザー権限として `student` と `teacher` を想定する。
- 投稿データは、ログイン中のユーザーと紐づけて保存する。

> 詳細は [`DB 設計`](./DB設計.md) を参照。

---

### 9. 外部連携・API 要件

| 外部サービス     | 概要                     | 方法     | 形式 |
| ---------------- | ------------------------ | -------- | ---- |
| `/auth/login`    | ログイン処理             | REST API | JSON |
| `/me`            | ログイン中ユーザー取得   | REST API | JSON |
| `/reports`       | 投稿一覧取得・作成       | REST API | JSON |
| `/reports/{id}`  | 投稿詳細取得・編集・削除 | REST API | JSON |
| `/admin/reports` | 全投稿一覧取得           | REST API | JSON |

> 詳細は [`API 設計`](./API設計.md) を参照。

---

### 10. 制約事項・前提条件

- フロントエンドは Next.js / TypeScript を利用する。
- バックエンドは Python / FastAPI を利用する。
- DBは PostgreSQL を利用する。
- ORMは SQLAlchemy または SQLModel を検討する。
- 認証方式は JWT を利用する。
- 1週間のMVP開発では、まず生徒本人の投稿作成・一覧・編集・削除を優先する。
- 講師用管理画面は Good to have とする。

---

### 11. リスクと対応方針

- 認証・認可の実装が複雑になる可能性がある
  - MVPではJWT認証と本人投稿のみ操作可能にする範囲を優先する。
- 画面数が増えて実装範囲が広がる可能性がある
  - `/login`、`/dashboard`、`/reports/new`、`/reports/{id}/edit` を優先する。
- バックエンドとフロントエンドの接続で時間がかかる可能性がある
  - API設計を先に整理し、必要なエンドポイントを明確にする。
- 管理画面まで実装する時間が足りない可能性がある
  - 管理画面はGood to haveとして扱い、MVP完了後に対応する。
